# Q-03 findings: full-stack Leptos implementation constraints

The approved architecture requires more than using Leptos as an HTML string
renderer. A feature-complete full-stack implementation needs one component
tree compiled twice:

- native SSR with Axum integration;
- `wasm32-unknown-unknown` hydration for browser interactivity.

cargo-leptos is the standard reproducible build path for this split. Browser
capabilities can remain in Rust through `gloo-net`, `web_sys`, and reactive
Leptos event handlers. wasm-bindgen's generated loader is unavoidable build
output, but it does not constitute a handwritten application layer.
